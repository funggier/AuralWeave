# AuralWeave v0.2.0-preview.2 — Monochrome Skin & Program Icon

Local development preview. GitHub Release v0.1.0 remains unchanged.

## Appearance and application identity

- Official monochrome AuralWeave icon (black/charcoal/silver) with alpha-transparent surroundings.
- Multi-resolution Windows .ico embedded in AuralWeave.exe, used by window title bar and taskbar.
- New UI theme system based on WPF resource dictionaries, with **Monochrome Dark** and **Graphite** built-in skins.
- Skin selector in the header; selection is saved to portable-relative `settings/appearance.json`.
- Redesigned three-stage layout: Sound Input → Filters → Sound Output, clean headers, restrained grayscale contrast, simpler cards, and dedicated live status.
- Unified Collapse all / Expand all shortcut for the visible filter controls and per-filter expand/collapse controls.

## Preserved behavior

- Native C++ WASAPI remains the **only** audio engine. UI skin switching does not restart audio or modify the buffer/latency path.
- Input meter, unique output routing, output mute/gain, start/stop button, live statistics, RNNoise Standard (optional), and repeated Gain effects remain supported.
- With RNNoise bypassed and no Gain effect, the audio route still uses its direct processing path.

## Scope clarification

The filter panel currently exposes **one RNNoise slot before the gain stages** and repeatable Gain filters. Although displayed under one Filters stage, truly arbitrary reordered/repeated RNNoise, Noise Gate, Limiter and other DSP modules are **not yet implemented** in the native processing graph. This UI prepares the visual design for that later work without falsely representing audio processing order.

## Testing & packaging

Native and .NET builds, portable publish, and UI startup should be validated before use. This preview is not a GitHub Release and is not installed automatically in `T:\Space\Products`.
