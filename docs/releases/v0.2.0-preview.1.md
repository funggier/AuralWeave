# AuralWeave v0.2.0-preview.1 — Local development preview

**Not published on GitHub Releases.** Existing GitHub v0.1.0 remains unchanged.

## Changes

- Native C++ WASAPI routing retained; Bypass remains the default and does not
  process RNNoise or add a denoising frame buffer.
- Xiph RNNoise v0.1.1 (standard embedded model) compiled directly into the
  native DLL; no separate DLL or online model download required.
- Noise Reduction dropdown now supports Bypass / RNNoise; switching can be
  performed while the route is running.
- Noise Model selector lists the bundled **Standard** model. Little and Custom
  are visibly unavailable until their model ABI and rights are verified.
- RNNoise accepts captured mono/stereo input using bounded 48-kHz/480-sample
  frame adapters and a separate RNNoise state per channel.
- Existing Gain Effects Chain and Multiple Outputs remain unchanged.

## Validation

- MSVC native build, native processing tests at 48/192 kHz mono/stereo,
  and .NET desktop compilation passed.
- Muted two-output hardware test with live Bypass → RNNoise → Bypass switching
  passed at 192 kHz input. A 10-second RNNoise soak recorded no buffer
  overruns, no new underruns after RNNoise was turned off, and no engine error.
- **Audible denoising quality and actual end-to-end latency are not yet
  validated.** RNNoise frame processing introduces buffering relative to Bypass.

## Known limits

- This version bundles only the RNNoise v0.1.1 Standard model, not newer
  Regular/Little weights.
- Current linear sample-rate conversion may introduce aliasing artifacts.
- No adaptive drift compensation, extensive device hotplug recovery, EQ,
  AI effects or virtual audio driver.
- Keep volume low and use headphones when manually testing microphone routing.
