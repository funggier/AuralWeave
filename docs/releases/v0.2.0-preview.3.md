# AuralWeave v0.2.0-preview.3 — Custom Window and Ordered Filters

Local development preview only. Published GitHub Release v0.1.0 is unchanged.

## UI changes

- Fully themed Windows window chrome: dark title bar, monochrome minimize / maximize / restore / close buttons, drag-to-move, double-click maximize/restore, right-click system menu and native-edge resizing.
- Monochrome Dark and Graphite skin resource dictionaries also style vertical/horizontal scrollbars, scroll thumbs and value sliders.
- START (light gray) / STOP (muted dark gray) on one stateful button.
- Filters initially contain **zero slots**. Clicking the full-width + button adds an empty slot displaying **Choose filter...**.
- Every filter slot may be independently enabled/disabled, collapsed/expanded, moved up/down or removed. The global shortcut initially says **Collapse all**, then **Expand all**, and toggles the whole list.
- Audio endpoint labels begin with the actual Windows `AudioEndpoint.Name`, then optional audio metadata in braces: `Line In (Realtek(R) Audio) {192 kHz · Stereo}`. Raw MMDevice IDs are never displayed in the selection text.

## Native audio changes

- Ordered Native C++ filter chain: the actual DSP order matches the displayed filter order; multiple instances of any supported filter have independent states.
- First supported types: Gain, RNNoise Standard v0.1.1, Noise Gate and Limiter.
- Empty slots and empty chains do not add any DSP to the capture/render audio processing path. Native C++ WASAPI remains the sole backend.
- Live filter reconfiguration uses a separately constructed processing graph and a packet-boundary atomic handoff. Slider changes are debounced.
- Noise Gate: threshold adjustable, 5 ms attack and 80 ms release (fixed in this preview).
- Limiter: ceiling adjustable, zero lookahead peak protection with 100 ms recovery. Fast transients can be affected.
- RNNoise: Standard built-in model only; duplicate RNNoise instances are permitted but each adds CPU load and 48 kHz frame processing.

## Caveats

- This is an experimental DSP implementation. Perceived denoising quality, gate behavior, limiter distortion, audio delay, clicks during filter replacement, and long-term independent-device clock drift still require user listening and formal measurement.
- RNNoise resampling uses linear interpolation (not yet high-quality anti-aliased conversion).
- This version is not a public/stable GitHub release.
- Project and ZIP remain under `T:\Space\Projects\ProjectsProgram\AuralWeave`. User's manually copied testing programs in `T:\Space\Products` are not overwritten.
